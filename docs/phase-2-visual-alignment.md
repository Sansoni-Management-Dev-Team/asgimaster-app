# Phase 2 — monochrome member app

The September 29 direction extends the approved black-and-white onboarding into the native member app. This supersedes the earlier teal calls to action and coloured Home progress categories for this implementation. The archived web prototype remains a historical reference.

## First-run Home and member identity — September 29

Entry now opens Home for new and returning members. A member with incomplete answers sees an intentional empty Home, with a setup/resume action and an explanation of what their direction will populate. The invitation and all seven questions remain the setup flow. New member data has no sample name, goal, completed lessons, learning minutes or weekly actions.

Completing onboarding saves the invitation name with the answers and brings the 12-month outcome into the Home plan. Home displays the challenge and growth priorities; those answers, industry and role inform lesson ranking. Questionnaire completion does not award learning progress or change membership access. Later answer edits refresh this context. Existing activity and explicitly customised plans are preserved; the old sample consultation goal is replaced by the member’s direction.

Profile opens with a clickable crown membership card showing the current plan, status and member identity, followed by the direction summary, grouped account actions and prototype tools. The lower Membership details action remains available alongside the card. Both open the membership screen. Membership has a distinct membership card, status explanation, accurate lesson/guidance/support access and working support actions for active, payment-due and paused states. It does not invent prices, renewal dates or billing records. Profile → Preview empty Home provides a non-destructive demonstration; choosing a demo learning preset remains an explicit activity replacement.

Validation: 94 Jest tests pass, including first-run routing, partial setup, answer/name persistence, edited-answer recommendations, legacy progress preservation, custom plans, failed-save retry, all four membership states and Coach before setup. TypeScript, design-token consistency and ESLint pass.

Browser verification used a separate localhost origin to preserve the original preview’s saved answers. The full first visit → invitation/name → seven answers → review → populated Home flow passes, with zero earned progress and a relevant first lesson. Name, answers and recommendations survive reload. Profile’s empty Home preview returns to the same saved direction; demo membership changes update the access screen. Empty Home, populated Home, Profile and Membership pass 20 layout checks across 320×568, 360×800, 390×844, 430×932 and 844×390, without horizontal overflow or controls below 48×48. Sequential keyboard focus is visible and scrolls member controls above the navigation footer. Screenshots are saved under `.expo/qa/`.

Device VoiceOver/TalkBack, 200% text scaling, native high contrast and software-keyboard checks remain unverified. This prototype iteration is not an accessibility conformance sign-off.

## Shared visual rules

- Use `design-system/tokens.css` as the source and regenerate native values with `npm run tokens:sync`.
- Use the white `accent` role for primary actions, selection, progress and highlights, with black `onAccent` text. Keep the original named semantic palette separate; do not redefine teal as white.
- Keep the application gradient almost black, with solid charcoal cards, quiet decorative borders and stronger neutral input boundaries.
- The Home membership shortcut uses a graphite card with fine vector grain, a soft diagonal reflection, a metallic rim and the white crown. The finish is static, uses shared neutral tokens and sits inside a 48×48 control that opens Profile.
- The full Profile membership card carries the same material: brushed graphite grain, a restrained diagonal reflection, a bevelled rim and an embossed crown. The compact landscape card shows the plan, status and member name when supplied, without a placeholder name, onboarding answers, a divider or a footer action label. Expiry sits at the bottom left and the card code at the bottom right. It uses 24px horizontal and 16px vertical insets, a 32px crown and 8px vertical gaps for a wider landscape silhouette, and grows naturally with enlarged text; the longer Essentials name adapts on narrow phones. The decorative finish is static and hidden from assistive technology. The whole card still opens membership details, alongside the lower account action.
- Card issuance is local prototype data: a one-year demo expiry and an eight-digit string code are saved on the first load, including for existing records. Codes display as `1234 5678`, preserving leading zeros. Existing 12-character hexadecimal codes convert once using their numeric value modulo 100,000,000, padded to eight digits. The migration saves only the changed code and preserves the original expiry, member data and other saved fields; a failed save retains the old record for retry. Reloading, answering onboarding or changing demo membership/activity presets preserves the card. Leap-day issuance expires on February 28 the following year. These fields are not billing records or access credentials and do not change entitlement rules; production must use the membership service's expiry and centrally assigned identifiers.
- The Profile card shows Active without a tick and omits the visible Expires and Card ID headings. The date remains at bottom left and the eight-digit code at bottom right; removing the labels naturally shortens the card. Expiry and card-ID descriptions are included in the card's accessible name on both web and native, with a separate navigation hint.
- Buttons and clickable rows use clear labels without decorative arrows or chevrons. Back and Send use visible text, with their accessible names and touch targets preserved.
- Match onboarding's 3.2-unit action corners, uppercase tracked headings and semibold copy. Keep round avatars and icon emblems where their shape has a purpose.
- Questionnaire headings use the 32px headline token with a 40px line height, matching the approved larger typography reference. Allow 32px between heading and supporting copy, 40px before answers, 16px between answer rows, and 8px between an option and its supporting label. Headings extend 16px into the content inset to preserve the reference's two-line layout on a 390px phone while reflowing on narrower screens.
- The final onboarding review follows the earlier completion reference: a thin circular crown, “This is your beginning” eyebrow, left-aligned title and introduction, then three ruled rows for the 12-month goal, challenge and growth. Each row has an underlined Edit action with a 48px target, followed by the white full-width “Enter my empire” action. The separate review opened from Home retains access to all seven saved answers. The new completion layout passes five phone viewport checks and keyboard traversal; edit routing and Home entry are covered by 18 onboarding tests.
- Identify progress by its label, value and accessible summary. Selected navigation also uses an underline, a surface and a programmatic state.
- Keep the existing 480-unit maximum content width, minimum 48-unit targets, flexible text heights and landscape footer reflow.
- Home, Library, Events, Coach and Support share `MemberHeader`: a left-aligned 28px uppercase title, a 48px control row, 4px top spacing and 24px below. Home's membership shortcut sits on the right with the other tabs' header controls. Context such as Coach availability appears below the title row. Library's redundant eyebrow and Events' separate options row are removed. Detail views retain their named Back actions. The screen-title size is a design token; headings and controls can wrap for enlarged text.

The shared theme covers Home, Library, Events, Coach, Support, profile/plan/membership views, lesson controls, forms and panels. Onboarding data, navigation and business models are unchanged by this visual update.
