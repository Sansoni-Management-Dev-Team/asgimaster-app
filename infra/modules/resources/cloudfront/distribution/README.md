# resources/cloudfront/distribution

Creates one or more CloudFront distributions from a YAML config file, where each distribution can mix any number of origins of different types in the same apply — a private S3 bucket via Origin Access Control (OAC), an Application Load Balancer, or a generic custom HTTP(S) origin (API Gateway, third-party domain, on-prem, an S3 static website endpoint). This is the module to use for a CDN that fronts more than one kind of origin, e.g. an ALB serving the app plus an S3 bucket for static assets on a separate path. If every origin in a distribution is a private S3 bucket, `resources/cloudfront/s3` is a narrower, simpler sibling.

Origin `type` drives how each origin resolves and how CloudFront reaches it. None of the three types are resolved by this module guessing a resource's name and looking it up via an AWS data source — every value that depends on another resource's existence comes in through a Terragrunt `dependency` block's outputs, wired to the appropriate override input. That keeps the real ordering requirement ("the bucket/ALB must exist before this module applies") visible to Terragrunt's dependency graph instead of hidden inside this module.

- **`s3`** — the module creates an `aws_cloudfront_origin_access_control` for it and needs the bucket's `id`, `arn`, and `bucket_regional_domain_name`, supplied via `s3_bucket_overrides` (keyed `"<distribution_key>:<origin_key>"`) from a `resources/s3` `dependency` block's `buckets` output. It also grants the OAC `s3:GetObject` on the bucket, scoped to the distribution's ARN, folding that grant into whatever policy the bucket already has (see "S3 origin bucket policy" below — identical behavior to `resources/cloudfront/s3`).
- **`alb`** — `domain_name` is required directly in `config.yml`, same as `custom` below. Usually that's a static hostname you control (a Route53 record pointed at the ALB, chosen to match its certificate — see "ALB origin certificate validation" below), so no `dependency` block is needed at all. The one case that does need one: pointing the origin straight at the ALB's own `*.elb.amazonaws.com` name, which is only known after `resources/lb/alb` applies — set a placeholder `domain_name` and supply the real `dns_name` via `origin_domain_name_overrides` from that module's `dependency` block.
- **`custom`** (the default when `type` is omitted) — any other HTTP(S) endpoint. Set `domain_name` directly in `config.yml`, or leave it as a placeholder and supply the real value via `origin_domain_name_overrides` for anything only known at the Terragrunt layer (e.g. an API Gateway invoke domain from a `dependency` block).

Every origin's final domain name can also be overridden at the Terragrunt layer via `origin_domain_name_overrides`, regardless of type — that wins over both an s3 origin's `s3_bucket_overrides`-derived domain name and a `config.yml` `domain_name`.

See `config/config.yml` for a worked example of each, including a mixed ALB + S3 distribution. Path-based routing to a second (or third) origin is done via `ordered_cache_behaviors`, same as any CloudFront distribution.

## ALB origin certificate validation

With `origin_protocol_policy: https-only` (the default for `alb` and `custom` origins), CloudFront terminates TLS to the origin and validates the origin's certificate against the domain name CloudFront is configured to connect to. For an `alb`-type origin pointed at the ALB's own `*.elb.amazonaws.com` DNS name, that's a mismatch — an ALB's HTTPS listener almost always presents a certificate for your actual custom domain instead, not for its AWS-assigned DNS name. That mismatch fails certificate validation and CloudFront returns a 502 to the viewer ("Generated by cloudfront"), even though the ALB, its listener, its target health, and its security group are all otherwise fine.

Fix it by pointing the origin at a hostname the ALB's certificate actually covers, instead of its raw DNS name: create a Route53 record under the same certificate's domain (e.g. a wildcard cert for `*.example.com` covers a record like `origin-app.example.com`) that resolves to the ALB, then set that origin's `domain_name` directly in `config.yml` — no `dependency` block needed, since you chose this hostname yourself:

```yaml
origins:
  alb:
    type: alb
    domain_name: origin-app.example.com
    origin_protocol_policy: https-only
```

If you'd rather point the origin straight at the ALB's own `dns_name` (e.g. `origin_protocol_policy: http-only`, sidestepping certificate validation entirely — CloudFront-to-origin traffic stays within the AWS backbone either way), that value is only known after `resources/lb/alb` applies, so it comes in via a real `dependency` block instead of a static `config.yml` value:

```yaml
origins:
  alb:
    type: alb
    domain_name: placeholder # overridden below
    origin_protocol_policy: http-only
```

```hcl
# in the calling terragrunt.hcl
dependency "alb" {
  config_path = "../lb/alb"
  # ...
}

inputs = {
  origin_domain_name_overrides = {
    "app:alb" = dependency.alb.outputs.load_balancers["web"].dns_name
  }
}
```

Most ALBs are set up to redirect HTTP to HTTPS, which makes `http-only` an incomplete fix on its own unless the listener is configured not to.

## S3 origin bucket policy

Identical to `resources/cloudfront/s3`: `aws_s3_bucket_policy` always sets a bucket's *entire* policy document, so before writing its own this module first reads the bucket's current policy and folds the CloudFront grant into it by `Sid`, keeping everything else already there (e.g. a `DenyInsecureTransport` statement from `resources/s3`'s `policy` field). This means **an `s3`-type origin's bucket must already have some policy attached** before this module's first apply — a bucket with no policy at all makes the read fail. Set `manage_bucket_policy: false` on that origin to opt out entirely.

Apply order matters for the same reason as `resources/cloudfront/s3`: if `resources/s3` (or anything else) applies its own static policy to the bucket after this module does, it overwrites the CloudFront grant until this module applies again. Keep this module last in your usual apply order for a given bucket.

## Sample Terragrunt Usage

```hcl
terraform {
  source = "git::https://github.com/<org>/terraform-modules.git//resources/cloudfront/distribution?ref=v0.0.1"
}

include "root" {
  path = find_in_parent_folders()
}

dependency "acm" {
  config_path = "../acm"

  # Lets `plan`/`validate` succeed before resources/acm has been applied
  # for the first time.
  mock_outputs_allowed_terraform_commands = ["init", "validate", "plan"]
  mock_outputs = {
    certificates = {
      cdn = { arn = "arn:aws:acm:us-east-1:123456789012:certificate/00000000-0000-0000-0000-000000000000" }
    }
  }
}

dependency "cloudfront_function" {
  config_path = "../cloudfront-function"

  mock_outputs_allowed_terraform_commands = ["init", "validate", "plan"]
  mock_outputs = {
    functions = {
      viewer-request-redirect = { arn = "arn:aws:cloudfront::123456789012:function/00000000-0000-0000-0000-000000000000" }
    }
  }
}

# Required for every s3-type origin (unless it sets its own domain_name) -
# this module no longer looks the bucket up by name, so Terragrunt's
# dependency graph (via this block) is what guarantees resources/s3 has
# already applied.
dependency "s3" {
  config_path = "../s3"

  mock_outputs_allowed_terraform_commands = ["init", "validate", "plan"]
  mock_outputs = {
    buckets = {
      static-assets = {
        id                          = "myapp-static-assets-production"
        arn                         = "arn:aws:s3:::myapp-static-assets-production"
        bucket_regional_domain_name = "myapp-static-assets-production.s3.ap-southeast-2.amazonaws.com"
      }
    }
  }
}

inputs = {
  project     = "myapp"
  environment = "production"
  config_file = "${get_terragrunt_dir()}/config/config.yml"

  # Same reasoning as resources/cloudfront/s3's acm_certificate_arn_overrides
  # and function_arn_overrides - config_file is read directly by Terraform
  # and never sees Terragrunt's $${dependency...} interpolation.
  acm_certificate_arn_overrides = {
    app = dependency.acm.outputs.certificates["cdn"].arn
  }

  function_arn_overrides = {
    "static_site:default:viewer-request" = dependency.cloudfront_function.outputs.functions["viewer-request-redirect"].arn
  }

  s3_bucket_overrides = {
    "app:static_assets" = dependency.s3.outputs.buckets["static-assets"]
  }

  # Needed for alb-type origins pointed straight at the ALB's own dns_name
  # (see "ALB origin certificate validation"), and for custom-type origins
  # whose domain name comes from a Terragrunt dependency block (e.g. an
  # API Gateway invoke URL).
  origin_domain_name_overrides = {}

  tags = {
    ManagedBy = "terraform"
  }
}
```

### config/config.yml

```yaml
distributions:
  # Web app served from an ALB, with a private S3 bucket for static assets
  # on a second path. alb's domain_name is a static Route53 hostname
  # (chosen to match the ALB's certificate) so it needs no dependency
  # block; static_assets' bucket id/arn/domain name come from the
  # s3_bucket_overrides input instead - see the Terragrunt usage above.
  app:
    comment: "App served from ALB with static assets from S3 on /static/*"
    aliases:
      - app.example.com
    origins:
      alb:
        type: alb
        # See "ALB origin certificate validation" above for why this is a
        # Route53 record rather than the ALB's own dns_name.
        domain_name: origin-app.example.com
        origin_protocol_policy: https-only
      static_assets:
        type: s3
        # bucket id/arn/bucket_regional_domain_name come from
        # s3_bucket_overrides["app:static_assets"] - no fields needed here
        # unless this origin's own domain_name should override that.
    default_cache_behavior:
      target_origin_id: alb
      viewer_protocol_policy: redirect-to-https
      allowed_methods: ["GET", "HEAD", "OPTIONS", "PUT", "POST", "PATCH", "DELETE"]
      cached_methods: ["GET", "HEAD"]
      forward_cookies: all
      forward_query_string: true
    ordered_cache_behaviors:
      static:
        path_pattern: /static/*
        target_origin_id: static_assets
        viewer_protocol_policy: redirect-to-https
        allowed_methods: ["GET", "HEAD"]
        cached_methods: ["GET", "HEAD"]
        cache_policy_id: 658327ea-f89d-4fab-a63d-7e88639e58f6 # AWS managed CachingOptimized
```

> `acm_certificate_arn` must reference a certificate in `us-east-1` regardless of the distribution's own region — CloudFront only reads ACM certificates from that region. Create it via `resources/acm` with `region = "us-east-1"`.

## Inputs

| Name | Description | Type | Default | Required |
|------|-------------|------|---------|----------|
| `region` | AWS region to use for the provider (CloudFront and its ACM certificate must be managed from `us-east-1`) | `string` | `"us-east-1"` | no |
| `project` | Project name, used as a prefix for distribution and OAC names | `string` | — | yes |
| `environment` | Deployment environment | `string` | `"develop"` | no |
| `config_file` | Absolute path to the YAML config file | `string` | — | yes |
| `tags` | Tags applied to all distributions | `map(string)` | `{}` | no |
| `origin_domain_name_overrides` | Map of `"<distribution_key>:<origin_key>"` to a domain name overriding any origin's resolved domain name — an `alb`/`custom`-type origin's `config.yml` `domain_name`, or an `s3`-type origin's `s3_bucket_overrides`-derived domain name (or its own `domain_name` override, if set) | `map(string)` | `{}` | no |
| `s3_bucket_overrides` | Map of `"<distribution_key>:<origin_key>"` to `{ id, arn, bucket_regional_domain_name }` for every `s3`-type origin (unless that origin sets its own `domain_name`). From a `resources/s3` `dependency` block's `buckets` output — this module no longer looks buckets up by name | `map(object({ id, arn, bucket_regional_domain_name }))` | `{}` | required for `s3`-type origins |
| `acm_certificate_arn_overrides` | Map of `distribution_key` to an ACM certificate ARN overriding that distribution's `config.yml` `acm_certificate_arn`. For the ARN from a `resources/acm` `dependency` block | `map(string)` | `{}` | no |
| `function_arn_overrides` | Map of `"<distribution_key>:<cache_behavior_key>:<event_type>"` to a CloudFront Function ARN overriding the matching `config.yml` `function_associations` entry's `function_arn`. `cache_behavior_key` is `"default"` for `default_cache_behavior`, or the key from `ordered_cache_behaviors`. For the ARN from a `resources/cloudfront/function` `dependency` block | `map(string)` | `{}` | no |

### config.yml distribution fields

| Field | Description | Default |

| `enabled` | Whether the distribution is enabled | `true` |
| `is_ipv6_enabled` | Enable IPv6 | `true` |
| `comment` | Distribution comment | `"${project}-${dist_key}-${environment}"` |
| `default_root_object` | Object returned for requests to `/` | `null` |
| `price_class` | `PriceClass_100`, `PriceClass_200`, or `PriceClass_All` | `"PriceClass_100"` |
| `aliases` | List of alternate domain names (CNAMEs) | `[]` |
| `acm_certificate_arn` | ACM certificate ARN (must be in `us-east-1`). Overridden by the module-level `acm_certificate_arn_overrides` input for the same `distribution_key` — never set this directly in `config.yml`. Omit (both here and in the override) to use the default `*.cloudfront.net` certificate | `null` |
| `minimum_protocol_version` | Minimum TLS version when `acm_certificate_arn` is set | `"TLSv1.2_2021"` |
| `web_acl_id` | WAF Web ACL ARN to associate | `null` |
| `http_version` | `http1.1`, `http2`, `http2and3`, or `http3` | `"http2"` |
| `wait_for_deployment` | Block until the distribution finishes deploying | `true` |
| `retain_on_delete` | Disable instead of destroying on `terraform destroy` | `false` |
| `origins` | Map of origin key to origin fields (see below) | required |
| `default_cache_behavior` | Default cache behavior fields (see below) | required |
| `ordered_cache_behaviors` | Map of path-based cache behaviors, evaluated in the order CloudFront receives them from the map (see below) | `{}` |
| `custom_error_responses` | List of `{ error_code, response_code, response_page_path, error_caching_min_ttl }` | `[]` |
| `geo_restriction` | `{ type, locations }` — `type` is `none`, `whitelist`, or `blacklist` | `{ type = "none" }` |
| `tags` | Per-distribution tags merged with the module-level `tags` variable | `{}` |

### origin fields

| Field | Description | Default |
|-------|-------------|---------|
| `type` | `s3`, `alb`, or `custom` | `"custom"` |
| `bucket_region` | `type: s3` only. Region the bucket actually lives in, if different from `var.region` (which defaults to `us-east-1` for CloudFront/ACM). Used for the `aws_s3_bucket_policy` this module attaches | `var.region` |
| `manage_bucket_policy` | `type: s3` only. Read the bucket's current policy and write it back with this origin's OAC grant folded in, scoped to this distribution's ARN. The bucket must already have some policy attached (see above). Set `false` only if the bucket's policy is managed elsewhere entirely | `true` |
| `extra_policy_statements` | `type: s3` only. List of additional IAM policy statement objects folded into the same document alongside the CloudFront grant and whatever else was already on the bucket. Each needs a unique `Sid` — re-applies use it to replace only the statements this module manages instead of duplicating them | `[]` |
| `domain_name` | Origin's domain name. Required for `type: alb`/`custom` (a static hostname you control, or a placeholder overridden via `origin_domain_name_overrides` — e.g. an ALB's raw `dns_name` or an API Gateway invoke domain, both only known from a Terragrunt `dependency` block). Optional for `type: s3` — set it only to override the `s3_bucket_overrides`-derived bucket domain name. Overridden by the module-level `origin_domain_name_overrides` input for the same `"<distribution_key>:<origin_key>"` | required for `alb`/`custom` |
| `origin_path` | Path prefix appended to every request to this origin (e.g. an API Gateway stage) | `""` |
| `origin_protocol_policy` | `type: alb` or `custom` only. `http-only`, `https-only`, or `match-viewer` | `"https-only"` |
| `http_port` / `https_port` | `type: alb` or `custom` only | `80` / `443` |
| `origin_ssl_protocols` | `type: alb` or `custom` only. TLS versions accepted talking to the origin | `["TLSv1.2"]` |
| `origin_read_timeout` / `origin_keepalive_timeout` | `type: alb` or `custom` only, in seconds | `30` / `5` |
| `custom_headers` | Map of header name to value sent to the origin on every request | `{}` |

### cache behavior fields (`default_cache_behavior` and each entry of `ordered_cache_behaviors`)

| Field | Description | Default |
|-------|-------------|---------|
| `path_pattern` | `ordered_cache_behaviors` entries only. Path pattern to match (e.g. `/api/*`) | required |
| `target_origin_id` | Key of the origin (from `origins`) to route to | required |
| `viewer_protocol_policy` | `allow-all`, `redirect-to-https`, or `https-only` | `"redirect-to-https"` |
| `allowed_methods` | HTTP methods CloudFront accepts from viewers | `["GET", "HEAD"]` |
| `cached_methods` | Subset of `allowed_methods` that gets cached | `["GET", "HEAD"]` |
| `compress` | Enable automatic compression | `true` |
| `cache_policy_id` | Managed or custom cache policy ID. When set, `forwarded_values`/TTL fields are omitted (mutually exclusive with them) | `null` |
| `origin_request_policy_id` | Managed or custom origin request policy ID | `null` |
| `response_headers_policy_id` | Managed or custom response headers policy ID | `null` |
| `forward_query_string` | Legacy mode only (`cache_policy_id` unset). Forward the query string to the origin | `false` |
| `forward_cookies` | Legacy mode only. `none`, `all`, or `whitelist` | `"none"` |
| `min_ttl` / `default_ttl` / `max_ttl` | Legacy mode only, in seconds | `0` / `3600` / `86400` |
| `function_associations` | List of `{ event_type, function_arn }` — attaches a CloudFront Function to this cache behavior. `event_type` is `viewer-request` or `viewer-response`. `function_arn` can be a static ARN here, or omitted and supplied via the module-level `function_arn_overrides` input keyed `"<dist_key>:default:<event_type>"` (default behavior) or `"<dist_key>:<ordered_cache_behaviors_key>:<event_type>"` | `[]` |
